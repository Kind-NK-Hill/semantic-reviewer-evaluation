## 8. 统计与判定的补充细节【补充】

**配对样本**：比较同一模型内的配置 X 与 R1 时，一道题至少在两种配置下各有 1 次有效判定，才进入这组比较。每题先在有效判定上取平均。每组比较都要报告被排除的题数。

**缺失界限**：每个比率给出两个界限：把缺失的判定全算判对（最好），和全算判错（最坏）。判定规则另在两种极端填补下各跑一次：X 取最坏、R1 取最好；X 取最好、R1 取最坏。三次结果不一致时，报告中写明“结论受缺失影响”。

**辅助指标的完整票数要求**：多数、一票否决、翻转率和 kappa，只在该配置下全部 m 次都有效的题上计算，并报告纳入的题数。

**kappa**：以二分类为主：接受（faithful）和不接受（unfaithful 或 uncertain），与主要指标的口径一致。三分类的 kappa 作为补充一并报告。

**明确判错的要求**：在不忠实题的有效判定中，计算明确判为 unfaithful 的比例：uncertain 留在分母里、分子计 0；失败和缺失不在分母中。取 R1 的比例减去 X 的比例，要求其 95% bootstrap 区间下界 > 0。漏放差满足第一步第 1 条、这一条却不满足时：
- 第一步的结果记为“R1 更常拒绝或弃权”；
- 第二步合成结论时，这种结果按“证据不足”处理，即维持 R1。

**措辞效应的比较方向**：计划要求拿“措辞版本与 R0 的差值”去比“R1 与 R0 的漏放差”。两者一律按**绝对值**比较，不管方向：措辞版本与 R0 的差值区间不含 0，并且 |措辞版本 − R0| ≥ |R1 − R0|（都用点估计）时，就要写上计划规定的那句话。R1 对 R1g 同样处理，用 |R1g − R1|。这是更保守的读法：措辞版本改善得比 R1 还多时，也会触发提示。

**bootstrap**：10,000 次重抽样，按规范化后的题面分组，用 `bootstrap` 种子。

**错误率控制的依据**：
- 每个可能出错的说法，都对应一个单侧 2.5% 的检验，即 95% 区间的一端：“显著更好”看下界是否 > 0，“不差于”看上界是否 < 5。“不差于”要求漏放和误拒两个指标同时满足，这是交并检验，不会放大错误率。
- 每个最终结论最多依赖两个这样的说法。例如“R1g 可替代 R1”依赖“R1 比 R0 显著更好”和“R1g 不差于 R1”。所以单个最终结论出错的概率不超过 5%。
- R1 对 R1g 的比较，只在 R1 对 R0 得出“显著更好”之后才用到（固定顺序）。把各条出错路径相加，每个模型得出错误结论的总概率在最坏情况下约为 7.5%，不是计划所说的“5% 以内”。最坏情况是：R1 确实比 R0 少漏，但 R0 在某个指标上差了 5 点以上，R1 与 R1g 的两种结论又都不成立。
- 报告中按“单个结论不超过 5%，整体最坏约 7.5%”来写，并记为判断点。
- 以上是在各检验都满足名义错误率的前提下做的**保守上界论证**。下面的模拟只检查区间覆盖率，以及三种配置完全相同时（S3）的结果；它没有验证这个上界，也没有证明上界能够达到。

**模拟验收**【补充】

数据生成规则（冻结时写进 `FREEZE.md`）：

- 题目结构与正式数据相同：288 道不忠实题、570 道忠实题，bootstrap 按正式数据的题面分组。
- 对每道题 i、每种配置 c、第 r 次，计算 z = a(c, 题目类别) + u_i + s_c·v_ic + s_r·e_icr。其中 u_i、v_ic、e_icr 都是独立的标准正态变量；z > 0 判“接受”（faithful），否则“不接受”。
  - u_i 由各种配置共用，使不同配置在同一题上的判定相关；
  - v_ic 是这种配置在这道题上的固定偏差，决定两种配置的不一致率，以及各次之间的相关；
  - e_icr 是每一次的随机波动。
- 截距 a 按目标比率解出：不忠实题上“接受”的比例等于目标漏放率，忠实题上“不接受”的比例等于目标误拒率。
- “不接受”中固定 20% 记为 uncertain，其余记为 unfaithful。
- 方差组合 (s_c, s_r) 取三组：(0.8, 0)、(0.5, 0.5)、(0, 0.8)。每组都报告模拟数据实际的 q 和 ρ。
- 每题次数 m：中间那组 (0.5, 0.5) 下 m 取 1、2、3；另外两组只做 m = 3。
- 每个场景、每种组合各模拟 1,000 次，用 `simulation` 种子。为节省时间，模拟中的 bootstrap 用 2,000 次；正式分析仍用 10,000 次。

| 场景 | 设定 | 验收标准 |
|---|---|---|
| S0 两配置相同 | 漏放 30%、误拒 15% | 漏放差 95% 区间的覆盖率在 93%–97% 之间；误判为“显著更好”的比例 ≤ 4% |
| S1 恰在界限上 | X 漏放 35%、R1 漏放 30%；误拒都是 15% | 误判为“不差于”的比例 ≤ 4% |
| S2 真有差别 | X 漏放 30%、R1 漏放 20%；误拒都是 15% | 只报告得出“显著更好”的比例，不设门槛 |
| S3 完整判定树 | R0、R1、R1g 三种配置完全相同（比率同 S0），跑完整的两步判定 | 最终结论中含“R1 显著更好”的比例 ≤ 4% |

不达标时：
- 先查实现，例如 bootstrap 写错、分组不对、正负号反了。是实现错误就修，然后重跑全部模拟。
- 排除实现错误后仍不达标，说明这种统计方法在这种数据结构下覆盖不足。这时记录下来，停在冻结之前（第 9 节）。
- 不得修改验收标准。

### 一句话与定位

在 ConsistencyCheck 去重后的 858 道人工标注题上，测量 AI 审核者判断“Lean 命题是否忠实于原题”时的漏放、误拒和成本，比较几套审核方案，并按事先写定的规则判断现有证据是否足以支持替换方案。

**定位**：工程导向的审核方法验证与复现扩展；不预先主张方法创新。

**主要问题**：在指定模型、数据与运行条件下，哪套审核方案产生怎样的漏放、误拒和成本，现有证据是否足以支持替换方案？

- 漏放：发布标签为不忠实、AI 判为忠实。误拒：发布标签为忠实、AI 判为不忠实或无法确定。
- 参照是冻结的发布标签。主分析测的是审核者与发布标签的一致程度；标签本身是否正确，只用“标签的机器核查”和“关键案例复核”做有限的检查。
- 与已有作品的分工：概率论形式化工作流、66 次主运行的过程评估，以及实际故障、交接、完成判定和成本分析，提供真实工作流和过程诊断的证据；其他项目已有数据质量处理、分组验证、基线比较和敏感性分析。本实验不需要独自证明这些能力，它补充的是在外部人工标注参照下对审核方案做前瞻验证，并支持具体的方案选择。
- 本实验不是完整的智能体能力评估：第一阶段的审核者是单次调用、没有工具的判定器。方法新颖性低，不等于没有研究能力；本实验的价值在于把现成方法用到一个具体选择上，并把证据和限制讲清楚。
- 已有工作：ReForm 已在 ConsistencyCheck 上比较过多个审核模型；arXiv 2408.08781 比较了评分细则的详细程度对多个评审模型的作用；RuVerBench 报告较弱的模型对提示变化更敏感。按 Astra 11 月 8 日的新颖性评估，本计划的每个组成部分都已有先例或部分先例，剩下的增量是这几套具体方案在这些条件下的实测证据。

**本实验能回答什么**

- 在 Terra 和 Flash 上，R0、R1、R1g 各自的漏放、误拒和成本，以及按来源的分布。
- 现有证据是否支持在 5 个百分点范围内用 R0 或 R1g 替代 R1。
- 重复判定、三次取多数、一票否决各带来什么取舍；单纯改措辞会让结果变多少。
- 去掉 R1 的某一条规则，在当前提示组合、模型和题集上影响多大（探索性）。
- 数据里有哪些重复、冲突和有机器证据的异常项。

**本实验不能回答什么**

- 哪个模型更强，或模型能力的一般规律。
- R1 的优势是否来自项目经验：R1 与 R1g 在内容、长度、结构上同时不同。
- 审核者的理由是否正确，即“真看懂”还是“碰巧判对”。
- 发布标签在语义上是否正确：机器核查只查编译和逻辑性质，关键案例在没有合格复核者时停在未决。
- 结论能否推广到原概率论项目或完整审核流程；审核者是否会主动利用验收漏洞。
